# Petstore API

A sample Pet Store Server based on the OpenAPI 3.0 specification

## Overview

This API client was generated by the [Dart-ACDC OpenAPI Generator](https://github.com/jhosm/Dart-ACDC-generator) for Petstore API.

## Features

- **Authentication (A)**: OAuth 2.1 with automatic token refresh and secure storage
- **Caching (C)**: Two-tier caching (Memory + Disk) with AES-256 encryption
- **Debugging (D)**: Configurable logging with sensitive data redaction
- **Client (C)**: Request deduplication, certificate pinning, offline support

## Requirements

- Dart SDK: >=3.0.0 <4.0.0
- Flutter: >=3.10.0

## Installation

Add this package to your `pubspec.yaml`:

```yaml
dependencies:
  petstore_client: ^1.0.0
```

Then generate JSON serialization code:

```bash
dart run build_runner build
```

### Full Configuration

```dart
final config = AcdcConfig(
  baseUrl: 'https://api.example.com',

  // OAuth 2.1 authentication with automatic token refresh
  auth: AuthConfig(
    tokenRefreshUrl: 'https://api.example.com/auth/refresh',
    clientId: 'your-client-id',
    clientSecret: 'your-client-secret',
    refreshThreshold: 300, // Refresh 5 minutes before expiry (seconds)
  ),

  // Two-tier caching (Memory L1 + Disk L2)
  cache: CacheConfig(
    ttl: Duration(minutes: 30),
    encryptCache: true,           // AES-256 encryption (default)
    maxMemoryCacheSizeMB: 10,     // In-memory LRU cache limit
    maxDiskCacheSizeMB: 50,       // Persistent disk cache limit
    userIsolation: true,          // Isolate cache per user (default)
  ),

  // Logging with sensitive data protection
  log: LogConfig(
    level: LogLevel.debug,        // none, error, warning, info, debug, verbose
    redactSensitiveData: true,    // Redact passwords, tokens in logs (default)
  ),

  // Offline detection
  offline: OfflineConfig(
    failFast: true,               // Throw immediately when offline (default)
  ),
);
```

## Authentication

### Setting Initial Tokens After Login

After your app's login flow completes, provide the tokens to the ACDC auth manager:

```dart
final dio = await ApiClient.createDio(config);
final authManager = dio.getAcdcAuthManager();

// After login, set the tokens obtained from your auth endpoint
await authManager.withInitialTokens(
  accessToken: loginResponse.accessToken,
  refreshToken: loginResponse.refreshToken,
);
```

### Automatic Token Refresh

Once tokens are set, ACDC handles refreshes automatically:

- **Reactive refresh**: When a 401 response is received, the token is refreshed and the request retried
- **Proactive refresh**: If `refreshThreshold` is set, tokens are refreshed before they expire
- **Request queuing**: Concurrent requests pause during refresh, then resume with the new token

### Logout

```dart
final authManager = dio.getAcdcAuthManager();

// Local logout (clear stored tokens)
await authManager.logout(revokeOnServer: false);

// Logout with server-side token revocation
await authManager.logout(
  revokeOnServer: true,
  revokeUrl: 'https://api.example.com/auth/revoke',
);
```

### Custom Token Provider

```dart
final config = AcdcConfig(

```

## Error Handling

All API methods throw typed exceptions from the `AcdcException` hierarchy:

```dart
try {
  final result = await api.someMethod();
} on AcdcAuthException catch (e) {
  // 401/403 responses, token refresh failures, invalid credentials
  // Recommended: redirect to login screen
  navigateToLogin();
} on AcdcNetworkException catch (e) {
  // No internet, connection timeouts, DNS resolution failures
  // Recommended: show connectivity message
  showOfflineMessage();
} on AcdcServerException catch (e) {
  // 5xx server errors
  // Recommended: show error message, offer retry
  showErrorWithRetry('Server error, please try again');
} on AcdcClientException catch (e) {
  // 4xx client errors (400, 404, etc.) except 401/403
  // Recommended: show validation errors
  showValidationErrors(e.message);
} on AcdcSecurityException catch (e) {
  // Certificate pinning failures
  // Recommended: warn user about security risk
  showSecurityWarning();
} on AcdcException catch (e) {
  // Catch-all for other ACDC errors
  showGenericError(e.message);
}
```

## Caching

### How It Works

Dart_acdc uses a two-tier caching architecture:

- **Memory (L1)**: LRU cache in RAM for fast access
- **Disk (L2)**: Hive-based persistent storage with optional AES-256 encryption

Cache keys automatically include the user ID (from the auth token), ensuring data isolation between users on shared devices.

### Per-Request Cache Control

```dart
// Bypass cache for a specific request
await dio.get('/data', options: Options(
  extra: {'cache_control': 'no-cache'},
));

// Force network request (skip cache entirely)
await dio.get('/data', options: Options(
  extra: {'force_network': true},
));
```

### Stale-While-Revalidate

Get cached data immediately while fetching fresh data in the background:

```dart
final stream = dio.streamRequest('/data');

stream.listen((response) {
  final source = response.extra['acdc_source']; // 'cache', 'network', 'stale', 'fresh'
  updateUI(response.data);
});
```

## Offline Support

When offline detection is enabled (`OfflineConfig`), the client checks connectivity before requests:

- **`failFast: true`** (default): Immediately throws `AcdcNetworkException` when offline with no cached response. Avoids connection timeout delays.
- **`failFast: false`**: Attempts the network call regardless. Useful when device connectivity checks are unreliable.

### Handling Offline Scenarios

**Read operations** — rely on cache:

```dart
try {
  final users = await api.getUsers();
  updateUI(users); // Data from network or cache
} on AcdcNetworkException {
  showOfflineMessage(); // Offline with no cache
}
```

**Write operations** — fail fast and queue locally:

```dart
try {
  await api.createUser(newUser);
} on AcdcNetworkException {
  // Queue the operation for later retry
  await localQueue.add(PendingOperation.createUser(newUser));
  showMessage('Saved offline. Will sync when connected.');
}
```

## Request Deduplication

Identical concurrent requests are automatically coalesced by dart_acdc. When multiple callers make the same request at the same time, only one network call is executed and the result is shared. This is enabled by default and requires no configuration.

```dart
// Both futures share a single network request
final future1 = dio.get('/users/123');
final future2 = dio.get('/users/123');

// Only one HTTP call is made; both resolve with the same response
final results = await Future.wait([future1, future2]);
```

Two requests are considered identical when they share the same HTTP method, URL, headers, request body, and response type.
